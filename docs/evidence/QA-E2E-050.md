# QA-E2E-050 — Login inválido e recuperação da interface

- Status: `failed`
- Defeito: `DEF-AUTH-001`
- Ambiente: Flutter Web/Chrome 151, ChromeDriver 151, API Express local efêmera, MySQL `barbearia_flutter_e2e_test` descartável.
- Reprodutibilidade: 2/2 execuções após a correção do orquestrador.
- Ator: visitante.
- Dados: `qa-invalid@getcutt.test` e senha sintética incorreta.

## Passos mínimos

1. Iniciar a API em porta efêmera com banco criado a partir das migrations.
2. Abrir o aplicativo Flutter Web pela landing.
3. Navegar para Login.
4. Informar e-mail inexistente e senha incorreta válida quanto ao tamanho.
5. Acionar Entrar e aguardar o fim do loading.

## Esperado

O erro não deve revelar se a conta existe, deve comunicar credenciais inválidas e o formulário deve continuar utilizável.

## Atual

A tela exibe `Sessão expirada. Faça login novamente.`. Os campos e o botão permanecem disponíveis.

## Causa confirmada por rastreamento

O backend responde 401 com `Credenciais inválidas.` em `src/controllers/auth.controller.js`. `ApiService._processarComRefresh` trata todo 401 como sessão expirada, tenta refresh e, quando não há refresh token, substitui o erro original pelo texto de sessão expirada. Login inicial não possui refresh token, logo a mensagem é semanticamente incorreta.

## Impacto

Feedback enganoso no login, confusão entre falha de credencial e expiração de sessão, além de impedir que o teste confirme o contrato esperado. Severidade média, prioridade P0 para homologação por afetar uma jornada básica.

## Regressão recomendada

Adicionar teste unitário para que 401 em `/auth/login` preserve `Credenciais inválidas.` e limitar refresh automático a requisições autenticadas que possuam refresh token. Depois repetir as três tentativas inválidas e o login correto sem recarregar.

## Cleanup

O banco `barbearia_flutter_e2e_test`, a API efêmera e o ChromeDriver iniciado pelo runner foram encerrados/removidos no `finally`.
